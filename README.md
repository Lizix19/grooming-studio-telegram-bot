# Telegram-бот для записи в груминг-студию

Telegram-бот на Python для онлайн-записи клиентов в груминг-студию для животных.
Пользователь выбирает вид и породу питомца, вводит данные владельца, выбирает
услуги и дополнительные материалы, свободную дату и время — бот сохраняет
запись в базу данных и считает итоговую стоимость. Отдельный раздел,
доступный только администраторам, позволяет просматривать и редактировать
данные в таблицах базы.

## Технологии

- Python 3
- [pyTelegramBotAPI](https://github.com/eternnoir/pyTelegramBotAPI) — работа с Telegram Bot API
- Microsoft SQL Server (через `pyodbc`) — хранение данных
- `python-dotenv` — загрузка секретов из `.env`-файла

## Структура базы данных

11 связанных таблиц с первичными и внешними ключами: справочники видов и
пород животных, клиенты и их питомцы, сотрудники, услуги и доп. материалы,
сама запись на услугу и связующие таблицы для отношений "многие ко многим".
Полная схема — в `db/schema.sql`.

## Установка и запуск (пошагово)

1. **Установите Python 3** (если ещё не установлен) — https://www.python.org/downloads/

2. **Скачайте проект** (клонируйте репозиторий или скачайте ZIP и распакуйте).

3. **Откройте терминал в папке проекта** и установите зависимости:
   ```
   pip install -r requirements.txt
   ```

4. **Установите ODBC Driver 17 for SQL Server**, если его ещё нет на вашем
   компьютере — он нужен библиотеке `pyodbc` для подключения к базе:
   https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server

5. **Создайте базу данных** в SQL Server и выполните в ней скрипт
   `db/schema.sql` (например, через SQL Server Management Studio).

   ⚠️ Важно: в `db/schema.sql` первичные ключи объявлены как обычный
   `int primary key`, без `IDENTITY`. Если в вашей реальной базе автоинкремент
   всё же включён — это нормально, просто скрипт не отражал этот момент.
   Если нет — при первой попытке добавить запись через сценарий бота
   (например, новый вид животного) вставка может завершиться ошибкой,
   потому что код не передаёт `id` вручную. Это нужно проверить именно
   на вашей базе — я не могу это проверить за вас, не видя реальной СУБД.

6. **Добавьте начальные данные.** Пустая база не позволит пройти сценарий
   записи — боту нечего будет предлагать. Возьмите `db/seed_example.sql`
   как образец (это шаблон, а не готовые данные вашей студии!) и замените
   значения на настоящие: виды/породы животных, услуги, хотя бы один сотрудник.

7. **Настройте секреты.** Скопируйте `.env.example` в файл `.env`:
   ```
   cp .env.example .env
   ```
   и заполните его:
   - `TELEGRAM_BOT_TOKEN` — токен вашего бота от [@BotFather](https://t.me/BotFather)
   - `DB_SERVER` и `DB_NAME` — имя вашего SQL Server и название базы данных
   - `ADMIN_USER_IDS` — ваш Telegram user_id (узнать можно у [@userinfobot](https://t.me/userinfobot)),
     через запятую, если админов несколько

   Файл `.env` никогда не попадёт в git — он уже в `.gitignore`.

8. **Запустите бота:**
   ```
   python bot.py
   ```
   В терминале должно появиться `Бот запущен`. Откройте бота в Telegram
   и отправьте `/start`.

## Что уже реализовано

- Пошаговый диалог записи: вид → порода → питомец → владелец → услуги →
  доп. материалы → дата → время → подтверждение
- Проверка занятости даты и времени
- Логика "найти или создать" для вида животного, породы и клиента (чтобы
  не плодить дубликаты в справочниках)
- Расчёт итоговой суммы с учётом услуг и доп. материалов
- Админ-раздел: просмотр/добавление/удаление/редактирование данных в
  таблицах, доступен только пользователям из `ADMIN_USER_IDS`

## Известные ограничения (честно, без приукрашивания)

- `id_sotrudnika` при записи всегда равен 1 — реального выбора сотрудника
  в сценарии записи пока нет
- Таблица `otzyvy` (отзывы) существует в схеме, но функционал отзывов не реализован
- Для больших таблиц вывод в Telegram обрезается (ограничение длины
  сообщения ~4096 символов)
- Нет автоматических тестов

Полный список изменений по сравнению с исходной версией — в `ИЗМЕНЕНИЯ.md`.

## Безопасность

- Токен бота и параметры подключения к БД хранятся только в `.env`,
  который не попадает в git
- Доступ к администрированию базы данных ограничен списком `ADMIN_USER_IDS`
- Администрирование БД работает через закрытый список разрешённых таблиц
  и столбцов (`utils.ALLOWED_TABLES`), значения передаются параметризованными
  SQL-запросами — прямое выполнение произвольного SQL от пользователя удалено
